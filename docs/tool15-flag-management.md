# 🚩 TOOL-15 実装：コンテキスト連携タスク・課題フラグ管理

TOOL-14 の生ログ層に「フラグ＋ステータス」を足し、**経営の見張り番**（見落とし防止）を実現する。
新DBは作らない。実データ・ビューは Notion、プロンプトはここで版管理。

## 1. 追加済みスキーマ（生ログ層2DB）
📋案件 `collection://92a82c51-6cb8-4656-9cd7-ad732fd2ddb9` / 🏢社内 `collection://1c7c87f8-eee0-4f6a-859c-209d335af72f` の両方に：
- `課題フラグ`（multi-select）：重要課題 / 悩み中・要相談 / 期限リスク・遅延 / 要決定
- `対応ステータス`（select・3段階）：未着手 / 対応中 / 完了
- `解決ソース`（url）：自動クローズ時の根拠URL

## 2. 作成済みビュー（Notion）
- **🚩 未解決フラグ**（board）… 両DBに作成。`課題フラグ`でグループ、`対応ステータス≠完了` で絞り、重要度順。
  → これが「見張り番」の一覧。

## 3. 🅰（取込＋集約）に追記する STEP④：フラグ付与＆自動クローズ
`daily-pipeline-prompt.md` の STEP② の後に、以下を追記する：

```
【STEP④ 課題フラグ付与＆自動クローズ（TOOL-15）】
1. 本日新規の生ログ（抽出日=本日）のうち 種別∈[論点・課題 / タスク / リスク] に、内容から `課題フラグ` を付与し、
   `対応ステータス`=未着手（未設定時）：
   - 重要度🔴高 or 経営影響大 → 重要課題
   - 判断に迷う/相談したい論調 → 悩み中・要相談
   - 期限が近い/超過 → 期限リスク・遅延
   - 承認/決裁待ち → 要決定
2. 自動クローズ：`対応ステータス`≠完了 かつ `課題フラグ`有 の既存レコードを、本日新規の生ログ/Slackと突合。
   明確な「完了/解決済み/対応済み/停止決定」の言及がある場合のみ `対応ステータス=完了` にし、
   `解決ソース`=根拠URL を記録、対象案件の集約「変更ログ」に1行残す（＝サイレント消失させない）。
   ※曖昧な言及ではクローズしない（保守的判定）。完了済みが再議論・未解決で再言及されたら `対応中` に戻す。
```

（朝ブリ本文の「🟠 気になる」の下に）

## 5. 🅲 週次エスカレ ルーチン（新規・アイデア#4の実装）
- name: `🗂️ 週次エスカレ（課題・タスクの見張り番）→#prv`
- cron: `0 23 * * 1`（＝**月曜 08:00 JST**）／新セッション方式／コネクタ: Notion＋Slack
- prompt（コピペ用）:

```
あなたはリード社の「課題・タスク 週次エスカレ（見張り番）」。毎週この時刻に、未解決の重要事項を棚卸しして #prv に投稿する。

【準備】ToolSearchで Notion(notion-query-data-sources) と Slack(slack_send_message)。基準日=本日(JST)。

【抽出】生ログ層2DB（92a82c51… / 1c7c87f8…）から：
- A. `課題フラグ`有 かつ `対応ステータス`≠完了（重要課題/悩み中・要相談/要決定/期限リスク・遅延）
- B. 種別='タスク' かつ `対応ステータス`≠完了 かつ 期限 ≤ 本日+7日（期限付き未完タスク）
案件横断で、重要度→期限の順に整理。抽出日が2週間以上前のものは「⏳滞留」を付ける。

【メッセージ（＠メンション不使用）】
🗂️ 週次エスカレ（YYYY/MM/DD）— 未解決の見張り番
🔴 重要課題 / 🟠 悩み中・要相談 / 🟣 要決定（承認待ち） / 🟡 期限リスク の順に、各行
「- [案件or社内] 要点（状態・期限・⏳滞留） <ソースURL>」。該当なしのセクションは省略。
全0件なら「未解決なし・クリア🎉」。

【投稿】slack_send_message で channel_id=C0A6NMGGR53（#prv）へ。投稿後リンクを出力。
```

## 6. 運用メモ
- フラグ付与・クローズはすべて 🅰（毎日04:00）が実施。人手の必須操作なし（ノーレビュー原則）。
- 誤クローズ対策：保守的判定＋`解決ソース`記録＋集約変更ログ＋再言及で再オープン。
- 完了判定を"実タスクDB"に厳密連携したい場合は将来拡張（山田タスク管理DB等との突合）。
