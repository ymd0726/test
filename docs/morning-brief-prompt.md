# ☀️ 朝ブリーフィング — ルーチン本体プロンプト（TOOL-14 機能追加 / #1＋#5＋#6 統合）

既存の🅱ルーチン（毎朝08:00 JST → #prv でタスク期限通知）を、この「朝ブリ」に**格上げ／置き換え**する。
1通で「今日の要対応＋昨日の動き＋放置/取りこぼしアラート」を届ける“朝の司令塔”。

## ルーチン設定
- name: `☀️ 朝ブリーフィング（→#prv）08:00 JST`（既存🅱を置換 or 新規）
- スケジュール: 毎日 08:00 JST（cron `0 23 * * *` UTC）
- 実行環境: Claude Code ルーチン（新セッション方式）／コネクタ: **Notion ＋ Slack**

## プロンプト（コピペ用）

```

【準備】ToolSearchで Notion(notion-query-data-sources / notion-fetch / notion-update-page) と Slack(slack_send_message / slack_read_thread / slack_get_reactions / slack_send_message_draft) を読み込む。基準日=本日(JST)、昨日=本日-1日。

【データソース】
- 集約コンテキストDB: collection://082df36b-76ce-41a5-bcb4-9ffea0d71c7a

- 生ログ層・🏢社内: collection://1c7c87f8-eee0-4f6a-859c-209d335af72f
- 議事録&施策DB: collection://500f63d4-3f8e-485a-a6ba-a0e3a3e7307a

━━ STEP0 消し込みスイープ（前日ブリの✅を反映）━━
1. #prv の**前回の朝ブリ親メッセージ**を特定（本文が「☀️ 朝ブリ」で始まる自分の直近投稿）。slack_read_thread でそのスレッド返信を全取得。
2. 各タスク返信メッセージの reactions を確認（slack_get_reactions 併用）。付いた絵文字で対象生ログ（返信末尾のNotionページURLからpage_id抽出）を notion-update-page：
   - ⚠️ page_id抽出時の注意：返信末尾のURLは Slack のリンク記法 `<https://app.notion.com/p/xxxx|link>`
     で入っている（APIが返す生テキストもこの形）。`<` `>` を除去し、`|` があればその**前**をURLとして扱ってから
     page_id（末尾32桁hex）を抽出すること。生URL形式の旧メッセージも同じ手順で扱える。
   - ✅(white_check_mark) → 対応ステータス=完了、解決ソース=「#prv ✅ YYYY-MM-DD」。
   - 🚫(no_entry_sign) → 対応ステータス=見送り（対応不要）。
   - 💤(zzz) → 次回通知日=本日+7日（date:次回通知日:start）。
3. 完了/見送りにした案件は、対象案件の集約「8.変更ログ」に1行残す（サイレント消失させない）。
※スイープが読めない/失敗しても**通知は止めない**（スキップして続行、運用ログに「スイープ失敗」と記録）。

━━ STEP1 収集 ━━
A. 今日の要対応（直近のみ）: 生ログ層2DBで 種別='タスク' かつ 【アクティブ】 かつ 期限(date:期限:start)∈[本日-1日〜本日+3日]。
   【アクティブ】= 対応ステータス ∉ {完了, 見送り（対応不要）} かつ（次回通知日 が空 OR date:次回通知日:start ≤ 本日）。
   🔴超過(本日-1) / 🟡今日・間近(本日〜本日+3)。案件横断・期限昇順。※古い超過(期限≤本日-2)は日次に出さず🅲週次に回す。
B. 昨日の動き: 生ログ層2DBで 抽出日=昨日 のレコードから 種別∈[決定事項/論点・課題/リスク/目標] を案件別に1〜2行で要約。
C. 🟠 鮮度アラート(#5): 集約DBで 状態='進行中' かつ 最終更新日 ≤ 本日-7日 の案件（＝1週間更新なし）。
D. 🟠 取込漏れ(#6): 議事録&施策DBで コンテキスト抽出済み≠__YES__ かつ（CLDB空 or 案件系Tag無し）の直近レコード上位5件。
E. 🚩 未解決の重要フラグ(TOOL-15): 生ログ層2DBで 課題フラグ有 かつ 【アクティブ】を、重要度順にtop5。
F. 🩺 ヘルスチェック（デッドマンスイッチ）: 運用ログページを notion-fetch し「## 実行ログ」に**昨日以降の🅰の行があるか**を確認。行が無い/❌失敗/⚠️部分失敗 なら異常と判定。

【安定運用ルール】
- SQLが失敗/タイムアウトしたら2s/4s/8sで最大3回リトライ→それでも失敗なら notion-fetch（ビュー/個別ページ）で代替取得。
  SELECTは必要列だけ・2DBは個別クエリ・LIKEやマルチセレクト絞込は避けて取得後に絞る。
- slack_send_message が失敗したら slack_send_message_draft で下書き作成にフォールバックし、その旨を運用ログに記録。
- 実行の最後に運用ログページ「## 実行ログ」直下へ必ず1行追記:
  `YYYY-MM-DD HH:MM JST | 🅱 | ✅成功/⚠️部分失敗/❌失敗 | スイープN件/要対応M件 | メモ`（失敗でも必ず書く）。

━━ STEP2 投稿（親1通＋要対応タスクをスレッド返信・＠メンション不使用）━━
【親メッセージ】slack_send_message で #prv(C0A6NMGGR53) へ：

━━ URL表記ルール（Slackリンク記法・本ルーチン共通）━━
- Slack本文のURLは **必ず `<URL|表示テキスト>`（Slack mrkdwn のリンク記法）** で出し、生URLを貼らない。
  表示テキストは既定で `link`。例：`<https://app.notion.com/p/xxxx|link>`
- `<ソースURL|link>` 等はプレースホルダ。**送信時は実URLに置換した完成形**にすること。

- スレッド返信のNotionページURLもリンク記法にするが、**STEP0の消し込みスイープが
  page_idを逆引きできる形を必ず保つ**（`<`/`>` を除去し `|` の前をURLとして扱えばよい）。

【投稿後】親メッセージのリンクを出力。0件でも親1通は必ず出す。

【注】完了/見送り/スヌーズは対応ステータス・次回通知日で管理。古い超過は🅲週次に集約。詳細は docs/morning-brief-prompt.md と同期。
```
