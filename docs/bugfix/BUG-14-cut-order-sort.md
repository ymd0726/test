## 0. スクショの言語化

> 注記: Notion MCP はプロパティ添付画像の署名付きURLを返さない（テキスト添付のみ
> ダウンロード可）ため、画像ピクセルは直接確認できず、以下は件名＋TOOL-24 v1.1 仕様
> からの推定（ユーザー確認済み: 2026-07-06「その認識でOK」）。

スクショは素材選定くんの**マッチング結果一覧UI**。各カットの素材候補が confidence
色分けカード（緑/黄/赤）で縦に並ぶ画面だが、並び順が**カット番号順ではなく信頼度の
低い順**になっており、例として「カット07（赤・要確認）が最上部、カット01が下方」の
ようにカット順がバラバラ。山田さんは「カット1から順番に並べてほしい」と指摘している。

## 1. 要望の要旨

マッチング結果を**カット1から番号順（昇順）**で表示してほしい。

## 2. 原因の特定

v1.1 の UI 改善で「confidence 色分けカード＋**低信頼度を先頭ソート**」を導入した
（TOOL-24 仕様に「低信頼度を自動的に先頭ソート」と明記）。これにより結果一覧の
**表示ソートキーが『カット順』→『信頼度昇順』に置き換わった**のが直接原因。

意図は「要確認カット（低信頼度）を先に人がチェックできるように」だったが、副作用として
カット順が崩れ、ユーザーが全体を追いにくくなった。

## 3. 修正方法

**既定の表示順をカット番号昇順に戻す**。実装は `scripts/match-sort/`（テスト済み）。

- `sortMatchesByCut(matches)` … カット番号昇順の安定ソート（同番号/不明は元順維持）
- `sortMatches(matches, mode)` … `"cut"`（既定）/ `"review"`（旧・低信頼度先頭）

結果描画直前のソートを差し替えるだけ:

```js
import { sortMatches } from "./match-sort/matchSort.mjs";

// 変更前: results.sort((a,b) => a.confidence - b.confidence) // 低信頼度先頭
// 変更後: const view = sortMatches(results, orderMode);      // 既定=カット順
```

各要素は `cut`（"カット03"）または数値 `cutIndex` を持てば自動整列。二桁カットでも
文字列ソートにならない（`カット2 < カット10`）。番号不明は末尾へ安定配置。

## 4. 改修・改善案（v1.1 の利点を失わない）

「低信頼度を先に確認したい」狙い（論点C＝パターンB）は、**並び替えではなく強調**で担保:

1. 既定は**カット順**で常に表示（本修正）。
2. 低信頼度カットは**赤＋「要確認」バッジ**で強調（色分けは v1.1 実装済みを流用）。
3. 画面上部に **[カット順 ⇄ 要確認順]** トグルを置き、必要時のみ `mode="review"` に切替。
   → 全体把握（カット順）と重点チェック（要確認順）を両立できる。

## 5. アイデア・機能追加への対応策

- **BUG-13 との相乗**: 各カット行に Drive のインラインプレビュー（BUG-13 対応）を
  カット順で並べれば、動画の流れに沿って素材を一望できる。
- **要確認件数の要約**: 「要確認 3/16 カット」をヘッダに表示し、トグルで該当だけ抽出。
- **書き戻し順の担保**: Notion への書き込みはカット別 callout 単位のため元々カット順だが、
  UI と一致させることで「見た順＝書かれた順」になり混乱を防ぐ。
