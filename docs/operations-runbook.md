# 🛟 運用ランブック（TOOL-14＋15 障害時の一次対応）

コンテキスト基盤（🅰取込＋集約＋フラグ / 🅱朝ブリ / 🅲週次エスカレ）が期待通り動かないときの対処手順。
まず **🩺運用ログページ**（`39435c2adb56810fa2b9d141ac273272`・/コンテキスト管理くん配下）を見る。

## 0. 異常の気づき方（正常系の確認先）
- 朝ブリ（毎朝08:00 #prv）の冒頭に `⚠️ パイプライン異常` が出る → 昨日の🅰が動いていない/失敗。
- 運用ログに昨日の行が無い → そのルーチンが起動すらしていない（ルーチン設定・課金・コネクタを疑う）。
- 週次エスカレ末尾の「🩺 直近7日」で成功率が下がっていないか。

## 1. Notion SQL（notion-query-data-sources）が失敗・タイムアウトする
症状：60秒タイムアウト／`Unexpected token '<'`（HTMLエラー）。Notion AI側の一時不調で断続的に発生する。
- ルーチンは自動で 3回リトライ→notion-fetch フォールバックする設計（プロンプト埋め込み済み）。基本は放置でよい。
- 手動で調べる場合：SELECT列を絞る／2DBを個別に叩く／LIKE・マルチセレクト条件をやめて取得後に絞る。
- 数日続く場合は Notion AI アドオンの状態（プラン・有効化）を確認。

## 2. Slack投稿が出ない
- live投稿（slack_send_message）が承認ゲートで失敗した場合、**#prvに下書き**が作られているはず
  （Slackの「下書き＆送信済み」を確認しワンタップ送信）。運用ログに「live失敗→下書き」と記録される。
- 下書きも無い場合：Slackコネクタがルーチンに紐づいているか（ルーチン編集画面のコネクタ設定）を確認。
- チャンネル変更したい場合：プロンプト内の channel_id（現行 #prv `C0A6NMGGR53`）を差し替え。

## 3. ルーチンが起動していない（運用ログに行が無い）
1. claude.ai/code/routines で該当ルーチンが**有効**か・cronが正しいか確認
   （🅰 `0 19 * * *`／🅱 `0 23 * * *`／🅲 `0 23 * * 1`、いずれもUTC）。
2. 手動で1回実行（ルーチンの手動実行）して動くか確認。動けばスケジュール側の問題。
3. プロンプトが最新版か確認（`docs/trigger-configs.md` の表から各最終版の場所へ）。

## 4. 誤クローズの戻し方（自動クローズが間違っていた）
対象の生ログレコード（📋案件/🏢社内コンテキストDB）で：
1. `対応ステータス` を `対応中`（または `未着手`）に戻す。
2. `解決ソース` をクリア。
3. 対象案件の集約レコード「8.変更ログ」に「YYYY-MM-DD: <課題> を誤クローズのため再オープン」を1行追記。
※次回🅰は「明確な解決言及」が無い限り再クローズしない（保守的判定）。

## 5. 二重登録・本文崩れが起きた
- 生ログの重複：どちらか一方を削除（`コンテキスト抽出済み`フラグとName突合が正常なら再発しない）。
- 集約本文の崩れ：直近の正しい状態へ手で直し、「8.変更ログ」に修正の1行を追記。次回マージは最新本文をベースに統合する。

## 6. フラグがノイズ化してきた
- 🅰のガードレール（1日最大5件・🔴高優先）が効いているか、運用ログの「フラグX」件数を確認。
- 週次エスカレの「⏳長期滞留（4週超）」枠に溜まったものは、人が判断して 完了 にするか捨てる（放置しない）。
