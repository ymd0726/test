# 当たり候補 自動判定（atari-kouho）

CR停止判定（ネガ側）のポジ版。**CPAが目標を下回る好調CRを自動で光らせる**仕組みを
集計表に入れる。セッション環境に Google 認証は無いため、読み書きはすべて
GitHub Actions（`ymd0726/test`）経由で行う。

## 1. 仕様（確定済み・勝手に変えない）

### 表示位置
- **消化金額列**（＝当たり判定プルダウンと同じ列）の **2行目**
- 2行目は各ブロックで `-` プレースホルダが入っているのでそこを置き換える
- プルダウン（5行目）には**絶対に触れない**。判定は表示専用

### 2段階（段階は新芽の数で表現。「予備軍」「🔥」「狼煙」は廃止語）
| 段階 | ラベル | 条件 |
|---|---|---|
| 1段階目 | `当たり候補🌱` | CPA ≤ 目標CPA×`data!S2` かつ 実質cv ≥ `data!S3` |
| 2段階目 | `当たり候補🌱🌱` | CPA ≤ 目標CPA×`data!S4` かつ 実質cv ≥ `data!S5` |

共通の前提ゲート: `消化金額 ≥ 目標CPA × 消化ライン`（データ量が足りないCRは点灯させない）

**必ず目標CPAを下回る時だけ点灯させる。** 係数を1.0超にすると目標より悪いCRが光るので不可。
量が多いだけの「量型」は対象外（CPA効率重視、というのがユーザーの明示的な判断）。

### 判定基準は data シートで編集可能にする
`data!R1:R5` にラベル、`data!S2:S5` に数値を置く。式はこのセルを参照するので、
**基準変更はシート上の数値編集だけで全CRに即反映**（ツール再実行は不要）。

**案件ごとにスプレッドシートが別なので、新しい案件では必ず先に data!R1:S5 を作る。**
未整備のまま当たり候補を入れると `目標CPA×空セル=0` となり永久に点灯しない。
作成は sheet-fix のパッチプランで行う（例:
`scripts/sheet-fix/plans/2026-07-29_nrn_atari-kouho-settings.json`）。

| セル | 内容 | jde での値 |
|---|---|---|
| S2 | 🌱 CPA係数（目標CPA×） | 0.9 |
| S3 | 🌱 実質cv下限 | 3 |
| S4 | 🌱🌱 CPA係数（目標CPA×） | 0.75 |
| S5 | 🌱🌱 実質cv下限 | 5 |

### 親子対応
親（子有り）は自身の指標が「子にて判定」で使えない。
**配下の子に1つでも該当があれば親にも表示**する（上位段階を優先）。

## 1.5 判定テキスト・中間コードの見た目
- 判定テキスト: `当たり候補🌱` / `当たり候補🌱🌱`（黒）。`--noroshi-col memo` でメモ列に出せる
- 中間コード: **プレーンな `0`/`1`/`2` のみ**（グレー）。cr識別子は同梱しない
  （過去に `cr39|1` のように識別子を同梱する形式を試したが、**Cmd+F でCR番号検索した際に
  中間コードのセルまでヒットして通常業務の妨げになる**という指摘を受け廃止した）。
  中間コードは常に**消化金額列**（＝ID行と同じ列）に置く。COUNTIFS でID行と列位置を
  揃えて突き合わせる設計上、中間行だけは列がID行と一致している必要があるため
  （メモ列には置けない）。判定テキストはメモ列でもよいが、中間コードは必ず消化金額列。

## 2. 式の設計（★ここが肝。崩さない）

**全ブロックで式は完全に同一**にする。親用・子用を書き分けない。
理由: CRは cr00 の列群を複製して増やすため、式がブロックごとに違うと
**追加のたびにツール再実行が必要**になってしまう（ユーザーからの明確な要求）。

そのために2つの仕掛けを使う:

### (a) 子の探索を式の中で動的に行う
親かどうかを事前判定せず、`COUNTIF` で「自分のID + `_*`」に一致するブロックを数える。
いれば子を集約、いなければ自分の判定を使う。**子を後から足しても親の式は書き換え不要**。

### (b) 中間行を挟んで循環参照を回避
表示行（2行目）で子を集約すると、子の表示セルも2行目にあるため循環参照になる。
判定結果を数値 0/1/2 で持つ**中間行**（例: 1103行目）を挟む。

```
中間行（1103行目・全ブロック同一）: 自分の指標だけで 0/1/2 を返す。他ブロックを参照しない
=IF(N(AI1101)<$W$5*$W$3,0,
  IF(AND(ISNUMBER(AQ1101),AQ1101<=$W$5*data!$S$4,N(AO1101)>=data!$S$5),2,
  IF(AND(ISNUMBER(AQ1101),AQ1101<=$W$5*data!$S$2,N(AO1101)>=data!$S$3),1,0)))

表示行（2行目・全ブロック同一）: 子がいれば子の中間行を集約、いなければ自分の中間行
=LET(id,AI6,kids,COUNTIF($6:$6,id&"_*"),
  t,IF(kids>0,
      IF(COUNTIFS($6:$6,id&"_*",$1103:$1103,2)>0,2,
      IF(COUNTIFS($6:$6,id&"_*",$1103:$1103,1)>0,1,0)),
      N(AI1103)),
  IF(t=2,"当たり候補🌱🌱",IF(t=1,"当たり候補🌱","")))
```

- 列参照（`AI6` `AI1103` `AI1101` `AQ…` `AO…`）はすべて**相対** → 列複製で自動追随
- `$6:$6` `$1103:$1103` `$W$5` `data!$S$2` は**絶対** → 全ブロック共通
- cr識別子は消化金額列と**同じ列**のID行にある（この前提が崩れると式が壊れる）
- 中間行は表示行が保護されたCRにも入れる → 手動注記があるCRも親の集約には効く

## 3. 横展開の手順

### Step 0: CLDB からスプレッドシートIDとタブ名を引く
Notion CLDB（データソース `collection://6ca19ba4-11c6-4d40-ad66-990c678b2b0d`）を
`notion-query-data-sources` で検索する。タイトル列は **`案件名`**（`n29_nrn` 形式）。
```sql
SELECT "案件名","案件正式名","集計表URL","集計表タブ名"
FROM "collection://6ca19ba4-11c6-4d40-ad66-990c678b2b0d"
WHERE "案件名" LIKE '%nrn%'
```

### Step 1: 対象タブの実測（思い込みで書かない）
`inspect-sheet.yml` を dispatch して以下を確定させる。

| 確認項目 | 確認方法 | jde の実例 |
|---|---|---|
| 目標CPAセル | 停止判定式（5行目等）が参照している `$W$5` 等 | W5 |
| 消化ラインセル | 同上の `$W$3` 等 | W3 |
| **指標行** | 停止判定式が参照している行番号。**タブごとに違う** | mak=1100 / kou=1101 |
| ID行 | 構造ダンプの「クリエイティブID行」 | 6 |
| 表示行2の中身 | `rows=2, formulas=true` でダンプ | `-` と手動注記が混在 |
| 中間行の空き | `cells=AI1103,EQ1103,…` で複数ブロックを抜き取り | 1103が空（1102は実データ） |

指標行を間違えると全CRが誤判定になる。**必ず既存の停止判定式から読み取る。**

#### 現在の配置（2026-08 時点。判定テキスト＝メモ列 / 中間コード＝消化金額列）
| 案件 | タブ | 判定テキスト（メモ列） | 中間コード（消化金額列・数値のみ） | 指標行 | 目標CPAセル |
|---|---|---|---|---|---|
| jde | kk_mak | 1098 | 1103 | 1101 | W5 |
| jde | kk_kou | 1098 | 1103 | 1101 | W5 |
| nrn | meta_total | 1005 | 1010 | 1008 | Z5 |

いずれも `--noroshi-col memo`（判定テキストのみメモ列に出す。中間コードは常に消化金額列）。
中間コードはグレー、判定テキストは黒。中間コードは `0`/`1`/`2` のプレーンな数値のみ
（cr識別子は同梱しない。Cmd+F検索を妨げないための仕様。詳細は1.5節）。

#### 行番号は案件ごとに実測する（規則性を当てにしない）
kk_mak には kk_kou に無い「当月着地」行があり、行構成が単純な1行ズレではない。
さらに **A列が空でもブロックのラベル行（消化金額/実質cv/CPA/メモ）である行がある**
（kk_mak の1097行目）。A列だけ見て空き行と判断してはいけない。
メモ列の値まで確認するか、dry-run にツールの保護判定を任せる
（ラベル「メモ」が入っていると全件除外され「書き込み可能なブロックがありません」で安全に止まる）。

#### 表示行はユーザーの見たい場所に置く。中間行は必ず別の空き行
判定テキストを出す行（`noroshi_row`）と中間コード0/1/2の行（`tier_row`）は
**必ず別行**にする（同じだと循環参照）。中間行は目に入らない空き行でよい。
表示行を動かすときは `clear_old_row` で旧行を掃除する。自作の式同士は
上書き可能なので、表示行↔中間行の入れ替えもそのまま実行できる。
現在の配置は上の「現在の配置」表を参照（jde/nrnとも判定テキスト=メモ列・中間コード=消化金額列）。

#### 表示行の候補は案件ごとに違う（決め打ちしない）
表示行は `--noroshi-col memo` を使えばメモ列の空き行でよく、消化金額列の2行目に
こだわる必要はない。メモ列に置けない/置きたくない場合のみ消化金額列側の空き行を探す。
プルダウン（当たり判定）と**同じ行番号**であることだけが必須（列はメモ/消化金額のどちらでもよい）。
ユーザーが手動でシート構成を変えることもあるため、依頼のたびに実測し直す
（例: jde kk_mak は当初2行目だったが、ユーザーがA1094を見出し行・A1097直下に空白行を
追加する形でレイアウトを変更し、表示行=1098・中間行=1103に移設した）。

#### 巨大タブの読み取り注意（nrn/rof 系）
列数が3,000を超えるタブは全面ダンプが Google 側で 503/タイムアウトになる。
- `dump=true` の全面ダンプは避け、`rows=2,6`（ID行と親子行）や `cells=` のピンポイント読取を使う
- 一時的な 503/404 が出ることがある。**共有権限を疑う前にまず再実行する**
  （spreadsheets.get が 404 でも、直後の再実行で通ることがある）
- ツールには 429/500/502/503/504 の指数バックオフ再試行を実装済み（2→4→8→16秒）。
  それでも落ちた場合は再実行してよい（式は冪等なので途中状態から安全に完了する）

### Step 2: dry-run
`noroshi.yml` を dispatch（`mode=dry-run`）。inputs は Step 1 の実測値。

ログで必ず確認する:
- `実CRブロック（当たり判定対象）` の件数が妥当か
- `中間行 NNNN: 全 N ブロックで書込可` … **非空があると中止する**。出たら別の空き行を選ぶ
- `表示行 2 に保護対象の内容があるため表示は見送り` … 手動注記（`エリア` `NG素材` 等）。
  これは**壊さないのが正解**。件数と中身をユーザーに報告する
- 点灯予測が実感と合うか（既知の当たりCRが光るか、目標CPAより悪いCRが光っていないか）
- 生成式が親・子で同一になっているか

### Step 3: apply
`mode=apply` で再 dispatch。`要目視確認 0 件` を確認。
undo ログがアーティファクト `noroshi-undo-log` に90日保存される。

### Step 4: 報告
書込セル数・点灯中のCR・保護したセル・undoログの場所をユーザーに伝える。

## 5. 安全策（実装済み。無効化しない）

- dry-run がデフォルト。`apply` 時のみ書き込み
- 表示行は「空 / `-` / 既存の当たり式」のみ上書き。**手動注記は保護して除外**
- 中間行は「空 / 既存の中間式」のみ。他の内容があれば**書き込まず中止**
- 5行目のプルダウンには一切触れない
- 書き込み前に undo ログ、書き込み後に再読取で全セル照合
- 既存の当たり式は上書き更新されるので、基準やラベルの変更は再実行で反映できる
