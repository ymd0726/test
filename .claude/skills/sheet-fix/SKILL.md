# 集計表 セル修正フロー（sheet-fix）

集計表への修正は**必ずこの手順で**行う。セッション環境に Google 認証は無いため、
読み書きはすべて GitHub Actions（`inspect-sheet.yml` / `sheet-fix.yml`）経由で実行する。

## 手順

### 1. 正本仕様を読む（スキップ禁止）
Notion「📊 集計表 構造仕様（全ツール共通リファレンス）」を fetch する:
`https://app.notion.com/p/39535c2adb568196a433dae934418ea1`
- §6 で対象案件の実測値（ID行・cr00位置・特殊事情）を確認
- §5「既知の罠」を確認（ID行クリア厳禁、結合セル、重複ID、マーカー変異 等）
- スプレッドシートID・タブ名は CLDB（案件別DB）を正とする。不明なら仕様書末尾の
  リンクドビュー経由で引くか、ユーザーに確認

### 2. 現状構造を実測する（思い込みで書かない）
GitHub Actions「集計表 構造ダンプ（cr入稿くん Phase 0）」（`inspect-sheet.yml`）を
`actions_run_trigger` で dispatch → `get_job_logs` で結果取得。
- inputs: `sheet`（スプレID）、`tab`（タブ名）、必要なら `dump=true`
- 修正対象セルの現在値・位置がプランの前提と合っているかここで確定させる
- 403 が出たら実行中サービスアカウント（ログ先頭に表示）への共有漏れを疑う（仕様書§7）

### 3. パッチプランを作りユーザーに承認をもらう
`scripts/sheet-fix/plans/YYYY-MM-DD_<案件キー>_<内容>.json` を作成
（形式は `scripts/sheet-fix/plans/README.md`）。
- `expectedBefore` は手順2で実測した現在値をそのまま入れる（`allowAnyBefore` は原則使わない）
- 対象は単一セルのみ。列挿入・ブロック複製など構造操作はこのフローの対象外
  （cr入稿くんGAS の領分。必要ならユーザーにその旨を伝える）
- **プラン内容（どのセルを何から何に変えるか）をユーザーに提示し、承認を得てから先へ進む**

### 4. dry-run
プランをコミット・push してから、`sheet-fix.yml` を dispatch:
- inputs: `plan`（repo相対パス）、`mode=dry-run`、**ref は push したブランチ**
- ログで「検証結果: OK n / 拒否 0」を確認。拒否があればプランを実態に合わせて修正して再実行

### 5. apply
`mode=apply` で再 dispatch。
- ログの「反映OK」を確認。「要目視確認」が出たセルは表示値をユーザーに報告
- undo ログがアーティファクト `undo-log` に90日保存される（before の値で書き戻せば復元可能）

### 6. 後始末（正本を育てる）
- 実測して構造仕様と差分があれば、Notion 仕様書§6 への追記・修正を行い、
  「最新バージョン」を上げて 📝変更履歴DB に1行追加する（仕様書§8の更新ルール）
- 結果をユーザーに報告: 変更セル一覧（before→after）、undo ログの場所、正本更新の有無
